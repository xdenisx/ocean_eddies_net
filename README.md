# Сегментация океанских вихрей

**Версия 2.0**

Пакет объединяет предобработку GeoTIFF-изображений, обучение нейронных сетей, инференс, постобработку и оценку качества. Поддерживается **бинарная и многоклассовая попиксельная сегментация**: каждому пикселю присваивается один класс, включая фон. Изображения могут содержать один или несколько каналов.

Ниже приведены примеры запуска из **Jupyter Notebook**. Их можно выполнять в `scripts/workflow.ipynb` или в отдельном ноутбуке.

## Нейросетевые архитектуры

В таблице указаны точные значения параметра `architecture`. Параметр `backend` определяет библиотеку, через которую создаётся сеть. При `backend: auto` используется основная реализация из таблицы.

| Архитектура | Значение `architecture` | Реализация (`backend`) |
|---|---|---|
| DeepLabV3+ с ResNet50 или ResNet101 | `deeplabv3plus_resnet50`, `deeplabv3plus_resnet101` | `smp` — segmentation_models_pytorch |
| U-Net++ с EfficientNet-B4 или B5 | `unetpp_effb4`, `unetpp_effb5` | `smp` |
| SegFormer B0, B2, B4 или B5 | `segformer_b0`, `segformer_b2`, `segformer_b4`, `segformer_b5` | `smp`; также доступна `hf` — transformers |
| UPerNet со Swin-Tiny или Swin-Small | `upernet_swin_t`, `upernet_swin_s` | `hf` |
| HRNet W18 или W32 с модулем сегментации из пакета | `hrnet_w18`, `hrnet_w32` | `timm` |
| TransUNet | `transunet` | `native` — встроенная реализация |
| Увеличенная TransUNet-подобная сеть | `sam_vit_unet` | `native`; |
| Простая сеть для проверки работоспособности на CPU | `tiny_unet` | `native`; служебная модель для тестов |

Все перечисленные сети получают число выходных классов из параметра `class_values`.

## Функции потерь

Функция потерь выбирается параметром `loss`. Все варианты поддерживают бинарную и многоклассовую сегментацию.

| Значение `loss` | Функция потерь | Что учитывает |
|---|---|---|
| `ce` | Cross-Entropy | Попиксельную ошибку классификации |
| `dice` | Dice Loss | Перекрытие предсказания и разметки через мягкий коэффициент Dice |
| `dice_ce` | Dice + Cross-Entropy | Сочетание Dice и попиксельной ошибки с равными весами |
| `focal` | Focal Loss | Снижает вклад уверенно и правильно классифицированных пикселей |
| `dice_focal` | Dice + Focal | Сочетание Dice и Focal Loss с равными весами |
| `tversky` | Tversky Loss | Позволяет отдельно задать штрафы за ложные срабатывания и пропуски |
| `focal_tversky` | Focal Tversky Loss | Степенное преобразование ошибки Tversky |

Веса классов `class_weights` задаются в том же порядке, что и `class_values`. Скалярный параметр `focal_alpha` действует только в бинарном случае. В Dice и Tversky фон по умолчанию не включается в усреднение по классам. Параметры `tversky_alpha` и `tversky_beta` задают штрафы за ложные срабатывания и пропуски соответственно.

### Общая функция запуска

Как и в исходном ноутбуке, все этапы запускаются через `run(...)`. Вспомогательная функция `run_python(...)` использует тот же интерпретатор, что и ядро Jupyter.

```python
import subprocess


def run_python(*args):
    command = [sys.executable, "-u", *map(str, args)]
    env = os.environ.copy()
    env["PYTHONIOENCODING"] = "utf-8"

    with subprocess.Popen(
        command,
        cwd=ROOT,
        env=env,
        stdout=subprocess.PIPE,
        stderr=subprocess.STDOUT,
        text=True,
        encoding="utf-8",
        errors="replace",
        bufsize=1,
    ) as process:
        try:
            for line in process.stdout:
                print(line, end="", flush=True)
            returncode = process.wait()
        except KeyboardInterrupt:
            process.terminate()
            try:
                process.wait(timeout=5)
            except subprocess.TimeoutExpired:
                process.kill()
                process.wait()
            raise

    if returncode != 0:
        raise subprocess.CalledProcessError(returncode, command)


def run(*args):
    run_python("-m", "ocean_eddy", *args)
```

## 2. Изображения и маски

Пример структуры данных:

```text
data/
├── train/
│   ├── images/scene_001.tif
│   └── masks/scene_001.tif
└── test/
    ├── images/scene_101.tif
    └── masks/scene_101.tif
```

У соответствующих изображения и маски должны совпадать относительный путь внутри своих папок, имя без расширения, размер, система координат (`CRS`) и геопривязка (`transform`). Маски должны быть одноканальными и содержать целочисленные коды классов.

Количество входных каналов задаётся параметром `in_channels`. Их порядок должен быть одинаковым при обучении, инференсе и проверке качества.

### Коды классов

Для бинарной сегментации используется схема **0 — фон, 255 — вихрь**. Пример многоклассовой схемы:

| Значение в маске | Название класса | Внутренний индекс сети |
|---|---|---|
| `0` | `background` — фон | `0` |
| `100` | `eddy_type_1` — первый тип вихрей | `1` |
| `255` | `eddy_type_2` — второй тип вихрей | `2` |

Названия и значения нужно заменить на соответствующие вашей разметке. Первый класс — фон. Число выходов сети автоматически равно длине списка `class_values`. Внутри модели используются последовательные индексы, а в выходной GeoTIFF записываются исходные коды классов. Поддерживаются также маски `0/1/2` и схемы с большим числом классов.

**Значение 255 не считается NoData, если оно указано в таблице классов.** Маски предсказаний сохраняются в формате `uint16` со значением NoData `65535` и внутренней маской валидности. Значения `0` и `255` остаются допустимыми кодами классов.

Параметр `ignore_values` задаёт коды, которые не участвуют в обучении и расчёте метрик. Для неизвестных значений маски доступны три режима `unknown_mask_policy`: `error` — сообщить об ошибке, `ignore` — исключить пиксели, `background` — отнести их к фону. По умолчанию используется `error`.

NoData, NaN, невалидные пиксели входных каналов и области, добавленные при дополнении тайлов до нужного размера, исключаются из функций потерь и метрик. Полностью пустые тайлы пропускаются. Если объявленное значение NoData маски совпадает с кодом класса, приоритет имеет таблица классов; явная маска валидности продолжает учитываться.

## 3. Обучение

### Настройка эксперимента в ноутбуке

Готовые конфигурации находятся в `configs/binary_deeplab.yaml` и `configs/multiclass_deeplab.yaml`. Их не обязательно редактировать вручную: следующая ячейка загружает шаблон и задаёт параметры прямо в ноутбуке.

Ниже показан пример **трёхклассовой сегментации** с DeepLabV3+ ResNet101. Перед запуском проверьте пути и схему разметки. Для каждого нового эксперимента используйте отдельный `output_dir`.

```python
import yaml
from ocean_eddy.config import TrainConfig

PARAMS = yaml.safe_load(
    (ROOT / "configs/multiclass_deeplab.yaml").read_text(encoding="utf-8")
)

PARAMS.update({
    # Данные и каталог результатов.
    "images_dir": "data/train/images",
    "masks_dir": "data/train/masks",
    "output_dir": "runs/deeplab_multiclass_trial",

    # Сеть, входные каналы и коды классов.
    "architecture": "deeplabv3plus_resnet101",
    "backend": "auto",
    "in_channels": 1,
    "class_values": [0, 100, 255],
    "class_names": ["background", "eddy_type_1", "eddy_type_2"],
    "ignore_values": [65535],
    "unknown_mask_policy": "error",

    # Тайлы, нормализация и аугментация.
    "tile_size": 512,
    "stride": 512,
    "normalize": "percentile",
    "zero_is_nodata": True,  # Для результатов HistEq + CLAHE задайте False.
    "augment_level": "heavy",
    "allow_flips": False,
    "min_positive_fraction": 0.0,

    # Функция потерь и параметры обучения.
    "loss": "dice_focal",
    "class_weights": [1.0, 1.0, 1.0],
    "batch_size": 1,
    "num_workers": 0,
    "freeze_batchnorm": True,
    "epochs": 150,
    "patience": 20,
    "early_stop_monitor": "val_iou",
    "min_delta": 0.001,
})
```

Для **бинарного обучения** замените в этой же ячейке `class_values` на `[0, 255]`, `class_names` — на `["background", "eddy"]`, а `class_weights` — на `[1.0, 1.0]`. Отдельно задавать число классов не нужно.


После изменения `PARAMS` повторно выполните ячейку сохранения конфигурации. Само изменение словаря не меняет уже сохранённый YAML-файл.

### Разделение данных и аугментация

По умолчанию набор делится **по сценам до нарезки на тайлы**. Нужны как минимум две сцены. Для зависимых или перекрывающихся снимков задайте собственный `split_file` с группировкой по району или времени съёмки: различие имён файлов само по себе не гарантирует независимость выборок.

Режим `split_mode: tile` доступен только как явно включаемый вариант и сопровождается предупреждением об утечке данных между обучающей и проверочной выборками. Фильтр `min_positive_fraction` действует только при обучении; в проверочной выборке фоновые тайлы сохраняются. По умолчанию этот порог равен `0`.

Размер тайлов по умолчанию — 512 × 512 пикселей. Доступны три уровня аугментации: `light`, `medium` и `heavy`. Чтобы отключить её, задайте `no_augment: true`. Аугментация применяется только к обучающей выборке. Если классы зависят от направления закрученности, оставьте `allow_flips: false`: отражение может изменить смысл метки.

### BatchNorm, ранняя остановка и результаты

При батче из одного изображения параметр `freeze_batchnorm: true` замораживает текущие статистики BatchNorm после каждого вызова `model.train()`. Обучаемые коэффициенты масштаба и смещения остаются доступными для оптимизации. Параметр `drop_last: true` применяется только при обучении. Накопление градиентов не увеличивает реальный размер батча для BatchNorm.

Ранняя остановка настраивается параметрами `patience`, `early_stop_monitor` и `min_delta`. Можно отслеживать `val_iou`, `val_dice` или `val_loss`. Для нескольких классов `val_iou` и `val_dice` — средние по нефоновым классам, для которых соответствующая метрика определена. Лучший checkpoint сохраняется при любом строгом улучшении; `min_delta` влияет только на сброс счётчика ожидания `patience`.

В `output_dir` сохраняются:

| Файлы | Содержание |
|---|---|
| `best_checkpoint.pt`, `last_checkpoint.pt` | Лучшее и последнее сохранённые состояния обучения |
| `history.json`, `training_log.csv` | История обучения и значения метрик по эпохам |
| `config.json`, `class_schema.json` | Параметры эксперимента и схема классов |
| `split.json`, `environment.json` | Разделение данных и сведения об окружении |

Архитектура и библиотека реализации сохраняются в checkpoint. При отсутствии нужной зависимости другая сеть не подставляется автоматически. В реализации Hugging Face параметр `pretrained: true` загружает предобученные веса, а не только конфигурацию.

## 4. Инференс и постобработка

После обучения задайте пути и запустите обработку тестовых изображений:

```python
CHECKPOINT = ROOT / PARAMS["output_dir"] / "best_checkpoint.pt"
TEST_IMAGES = ROOT / "data/test/images"
TEST_MASKS = ROOT / "data/test/masks"
PREDICTIONS = ROOT / "predictions/multiclass"

# При работе с ранее обученной моделью укажите CHECKPOINT вручную.
run(
    "infer",
    "--input", TEST_IMAGES,
    "--checkpoint", CHECKPOINT,
    "--output_dir", PREDICTIONS,
    "--tile_size", 512,
    "--stride", 256,
    "--blend_mode", "distance",
    "--smooth_sigma", 1.0,
    "--min_object_size", 200,
    "--min_hole_size", 100,
    "--save_prob",
    "--save_raw_prob",
)
```

Архитектура, схема классов, число каналов и нормализация берутся из checkpoint. Веса загружаются строго: несовпадение структуры модели не скрывается предупреждением.

Для объединения перекрывающихся тайлов доступны весовые окна `uniform`, `distance`, `hann` и `gaussian`. Параметр `stride` задаёт шаг тайлов. В приведённом примере тайлы размером 512 × 512 сдвигаются на 256 пикселей.

**Сглаживаются вероятности, а не числовые коды классов.** Малые объекты удаляются отдельно для каждого класса. Небольшие отверстия внутри объектов заполняются только там, где нет другого класса или NoData. Размеры объектов и отверстий задаются в пикселях, `smooth_sigma` — также в пикселях.

Для бинарной сети в вызов `run(...)` можно добавить аргументы `"--threshold", 0.35`. Для многоклассовой сети используется `argmax`: каждому пикселю назначается класс с наибольшей вероятностью.

Параметр `class_min_sizes` позволяет задать разные минимальные размеры объектов для разных классов. Например, пара аргументов `"--class_min_sizes", '{"100": 200, "255": 100}'` задаёт минимум 200 пикселей для класса `100` и 100 пикселей для класса `255`.

Порог вероятности и параметры постобработки подбирайте на проверочной выборке, а не на итоговой тестовой.

| Выходной файл | Содержание |
|---|---|
| `scene_pred.tif` | Итоговые коды классов после постобработки |
| `scene_pred_prob.tif` | Вероятности после сглаживания, до удаления объектов и заполнения отверстий |
| `scene_pred_raw_prob.tif` | Вероятности после взвешенного объединения тайлов, до сглаживания |

Вероятностные GeoTIFF содержат по одному каналу на класс, включая фон, в порядке `class_values`. NoData в вероятностях обозначается как NaN.

Вероятности всех классов накапливаются на диске; параметр `work_dir` задаёт временный каталог. При этом оперативная память всё равно требуется для целых двумерных карт и обработки связных компонент.

## 5. Проверка качества

Используйте те же `CHECKPOINT`, `TEST_IMAGES`, `TEST_MASKS` и `PREDICTIONS`, что и при инференсе:

```python
METRICS = ROOT / "metrics/multiclass"

run(
    "validate",
    "--pred_dir", PREDICTIONS,
    "--mask_dir", TEST_MASKS,
    "--images_dir", TEST_IMAGES,
    "--checkpoint", CHECKPOINT,
    "--output_dir", METRICS,
)
```

Рассчитываются IoU, Dice/F1, precision, recall, specificity, accuracy и числа TP/FP/FN/TN, а также поклассовые и средние показатели. Общая матрица ошибок накапливается по всем пригодным пикселям; итоговые метрики не являются средним арифметическим метрик отдельных батчей.

В матрице ошибок строки соответствуют эталонным классам, столбцы — предсказанным. Неопределённые метрики записываются как `null`, а не как `1`. Пропуски и исключённые области отражаются в отчёте.

Основные результаты сохраняются в `metrics_summary.json`, `metrics_per_image.csv`, `metrics_per_class.csv`, `metrics_per_image_class.csv` и `confusion_matrix.csv`. Это **попиксельные метрики**; оценка отдельных вихрей как объектов в этой версии не реализована.

## 6. Предобработка HistEq + CLAHE

Этот этап необязателен. Если он нужен, выполните его **до обучения** и одинаково обработайте обучающие, валидационные и тестовые изображения. В приведённой структуре проверочная выборка определяется из `data/train`, поэтому она проходит ту же предобработку.

```python
for subset in ("train", "test"):
    run(
        "preprocess",
        "--input_dir", ROOT / "data" / subset / "images",
        "--output_dir", ROOT / "data" / subset / "images_hist_clahe",
        "--clip_limit", 0.03,
        "--kernel_size", 0,
    )
```

Последовательность операций:

```text
Нормализация в [0, 1] через cv2.normalize
    → глобальное выравнивание гистограммы: equalize_hist
    → CLAHE: equalize_adapthist
    → нормализация в [0, 255] и преобразование в uint8
```

Имена файлов и геопривязка сохраняются. Каналы обрабатываются отдельно. Флаг `skip_equalize_hist` отменяет применение выравнивание контрастов на основе алгоритма CLAHE. Параметр `kernel_size` задаёт размер локальной области в пикселях; `0` означает автоматический выбор. Маски классов предобрабатывать не нужно.

**Для обработанных изображений задайте `zero_is_nodata: false`: ноль теперь может быть корректной яркостью.** Перед сохранением конфигурации и запуском обучения в разделе 3 измените `images_dir` на `data/train/images_hist_clahe` и `zero_is_nodata` на `False` в словаре `PARAMS`. Для инференса и оценки качества используйте `TEST_IMAGES = ROOT / "data/test/images_hist_clahe"`.

Настройка `zero_is_nodata` сохраняется в checkpoint. Не смешивайте исходные и предобработанные изображения на разных этапах одного эксперимента.
